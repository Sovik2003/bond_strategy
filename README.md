# bond_strategy

Аналитическое ядро облигационной стратегии: загрузка данных MOEX ISS,
отбор выпусков, расчёт доходности, сигналы и виртуальный портфель.

Только анализ и виртуальные операции. Брокерских подключений и реальных
заявок нет.

## Что внутри

| Модуль | Назначение |
|---|---|
| `models.py` | Доменные структуры и статусы данных |
| `config.py` | Конфигурация с `config_id` — решения воспроизводимы |
| `validation/freshness.py` | Проверка свежести критических полей |
| `analytics/cashflows.py` | График купонов, амортизации, погашения; XIRR |
| `analytics/yield_calc.py` | Доходность к погашению с НКД и комиссией |
| `analytics/scoring.py` | Скоринг: кредит, финансы, доходность, ликвидность, срок |
| `ingestion/moex.py` | HTTP-клиент ISS, разбор блоков, пагинация bondization |
| `ingestion/mapping.py` | Сборка `BondIssue` из сырых ответов ISS |
| `signals/filters.py` | Жёсткие фильтры с кодами отказа |
| `signals/generator.py` | Цепочка «фильтр → доходность → балл → лимиты → сигнал» |
| `portfolio/engine.py` | Позиции, лимиты, купоны, амортизация, погашение |
| `pipeline.py` | Конвейер: ISS → отбор → нормализация → скрининг → отчёт |

## Запуск

```bash
pip install -e ".[dev]"

python -m pytest              # 334 теста, сеть не нужна
```

Прогон на живых данных MOEX ISS:

```python
from datetime import date
from bond_strategy.config import load_config
from bond_strategy.ingestion.moex import IssClient
from bond_strategy.pipeline import run_pipeline

cfg = load_config("config/strategy.json")
client = IssClient(raw_root="data/raw")
result = run_pipeline(date(2026, 10, 26), cfg, client, limit=20)
print(result.summary)
```

## Ребалансировка портфеля

Отдельный слой от скринера: скринер отвечает «что интересно купить»,
ребалансировка — «что купить и в каком количестве на уже собранном портфеле».
Пороги живут в `config/rebalance.json` (отдельно от `strategy.json`, потому что
это другой набор решений), портфель — в `data/portfolio.json`.

Два способа запуска — из интерфейса и из командной строки.

**Интерфейс.** `streamlit run app.py` открывает скринер; рядом в меню слева
появляется страница «Ребалансировка» (`pages/2_Ребалансировка.py`). На ней:
форма портфеля, кнопка запуска, рекомендации, статусы позиций, структура
«до/после» и график ожидаемых выплат. Отдельная страница, а не вкладка:
`app.py` — линейный скрипт с `st.stop()`, а вкладки в Streamlit не изолируют
исполнение, поэтому остановка в одной погасила бы и соседнюю.

**Командная строка.**

```bash
# портфель: {"cash": 75000, "positions": [{"secid": "RU000A101H84", "quantity": 10}]}
python -m bond_strategy.cli rebalance --date 2026-10-26
```

Форма портфеля общая для обеих страниц (`ui_portfolio.py`): портфель — один
объект в `data/portfolio.json`, и две копии формы разошлись бы с ним.

Загрузка рынка идёт страницами с кэшем на диске (`data/cache`). Обогащение
выпуска — четыре сетевых запроса, при 325 выпусках это больше тысячи запросов,
поэтому обрыв не должен обнулять работу: каждая страница сразу сохраняется, а
повторный запуск продолжает с места остановки. Ключ кэша привязан к дате
расчёта и `config_id`, так что старые данные в новый расчёт не подмешиваются.

Полезные параметры: `--limit` (собрать часть рынка, посмотреть отчёт,
продолжить позже), `--page-size` (сколько выпусков за один заход), `--workers`.

Модули: `snapshot` — состояние и проекция сделки, `eligibility` — допуск по
разделу 3, `limits` — лимиты концентрации, `positions` — статусы позиций,
`planner` — жадный подбор покупок, `report` — отчёт «до/после»,
`market_cache` — дисковый кэш, `iss` — постраничная загрузка.

### Что важно знать про правила

- **Продажа только при ухудшении риска.** Снижение цены, рост ставок, выход
  доли за лимит из-за цены и отклонение от лестницы сроков — не причины
  продажи. Отсутствие рейтинга — «проверить риск», а не продажа.
- **Лимиты не ухудшать.** Если отрасль уже выше 25%, покупка бумаги другой
  отрасли разрешена: из нарушения нельзя выйти, если запрещены любые сделки.
- **Доходность не перекрывает риск.** Критерии шага 5 — приоритеты, а не веса:
  сначала концентрация, потом интервал сроков, потом рейтинг, купоны и только
  при равенстве — доходность.
- **Остаток остаётся на счёте**, если выбор между нарушением ограничений и
  деньгами. Причина остатка указывается в отчёте.

## Принципы

1. **Отказ важнее догадки.** Нет цены, НКД, купона или рейтинга — `BUY` не
   формируется. Отсутствующее значение остаётся `None`, а не нулём.
2. **Статус данных блокирует покупку.** `STALE`, `MISSING`, `CONFLICT`,
   `UNVERIFIED` по критическому полю → `DATA_BLOCKED`.
3. **Идемпотентность.** У купона и амортизации есть уникальный ключ события:
   повторная загрузка не начисляет выплату второй раз.
4. **Сырой ответ сохраняется** до нормализации, вместе с SHA-256.
5. **Доходность не подставляется нулём.** Если XIRR не сошёлся — `ok=False`.

## Особенности MOEX ISS, учтённые в коде

- `bondization` отдаёт по 20 строк на страницу — блок дочитывается до конца,
  иначе теряется часть графика купонов.
- Строка `data_source='maturity'` в амортизациях — это погашение, а не
  амортизация; учитывать её дважды нельзя.
- `FACEVALUE` — остаточный номинал после амортизации, `INITIALFACEVALUE` —
  исходный. Доли амортизации считаются от исходного, а купон платится от
  ОСТАТОЧНОГО: у бумаги с номиналом 50 ₽ из 1000 ₽ купон в 20 раз меньше, чем
  дала бы база `initial_nominal`.
- `ACCRUEDINT` — накопленный купонный доход в РУБЛЯХ на бумагу, а `PREVPRICE` —
  в процентах от номинала. Складывать их нельзя: получается цена в полтора
  раза выше рыночной и отрицательная доходность у бумаг с купоном 14–16%.
- Будущие купоны приходят с ПУСТЫМИ суммами (`value: null`): ISS знает даты, но
  не суммы. График, обрезанный до одной выплаты, нельзя принимать за полный —
  недостающие суммы восстанавливаются по ставке из описания выпуска.
- В ISS нет рейтинга, отрасли и названия эмитента. Они берутся из
  `config/issuers.json`. Пустой справочник — валидное состояние: тогда ни
  один выпуск не получит `BUY`, и это корректно, а не сбой.
- `BOND_TYPE` описывает способ погашения, а не тип купона. Тип купона
  определяется по `COUPON_BENCHMARK` и `COUPON_DETAILS`.

## Ограничения

- налоги не рассчитываются;
- комиссия задаётся ставкой из конфигурации, а не договором брокера;
- справочник эмитентов (`config/issuers.json`) заполняется вручную;
- истории решений в БД нет — экспорт в JSON.
